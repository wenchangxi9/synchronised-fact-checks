# X 官方“Posts with the same media”页面的批量入口

`media_note_page_candidates.csv`由官方notes源文件中`isMediaNote=1`的160,767条记录生成。每一行用`noteId`构造候选地址`https://x.com/i/communitynotes/m/{noteId}`，同时保留原帖`tweetId`、note创建时间和现有状态。来源是本项目截至2026年7月26日选定的media-note队列（底层notes快照为2026年8月24日），因此不覆盖此后的新增notes。

候选地址不等于已经确认存在跨帖匹配。实测`/m/1765016738255573076`和`/m/1841871403055714728`显示多个匹配帖；`/m/1665007772029575168`可打开但当前提示“没有匹配”。批量采集时，应访问页面、滚动到末尾、提取页面列出的帖子ID，并记录抓取时间、是否为空、是否遇到登录或加载错误。

研究分组以“同一页面列出的帖子”为可观察的X平台匹配组，原帖`tweetId`应单独作为锚点保留。不同note的页面可能重叠，不能只凭某个帖子同时出现在两页就合并两个媒体组，因为一个帖子可能含多件媒体。页面列出“同媒体”也不等于该note已在每条帖子上向所有用户显示；显示需要额外的Helpful状态及适用性共识。

`official_page_matches_pilot.csv`只记录已在X页面上实际看到的note—post关系。`complete_page`表示滚动到页面末尾且重复检查无新帖；`partial_page`表示只收集了部分已经展示的帖子，不能用于计算该组的完整规模。当前试验含1个完整组（3个帖子）和2个部分组（分别已见20、23个帖子），共46条不重复关系。另一个在此前轮次核实完整的8帖页面保存在`2101017095244828916_posts.csv`。

## 提速检查（2026-09-29）

`media_note_fetch_queue.csv`由`scripts/prepare_media_match_queue.py`生成，保留全部160,767个media note。最新排序优先未查询、已有跨帖评分目标的note，再按Helpful等状态和提交时间排序。快照中Helpful共28,539条。已观察页面排在后面并标记`previouslyObserved`，其中partial_page仍需续采，不表示已完成。`knownRatingTargets`仅用于安排查询顺序，不能替代官方页面确认。**其余note也不据此判为无匹配**。队列会重新排序，恢复时应按noteId和日志判断，不应仅使用旧queueRank。

页面的X网页代码使用`BirdwatchFetchMediaMatchSlice`请求获取列表，并有分页字段`slice_info`。直接读该列表理论上能免去逐页渲染和滚动；但在当前匿名会话中，使用从网页代码解析的当期query ID请求返回空体HTTP 404，加入访客令牌和客户端交易ID后仍如此。浏览器内该接口地址还被浏览器客户端拦截。故目前不能把直连接口当成已验证的采集方法，更不能将404计为“无匹配”。只有页面实际显示且核对过的帖子保留在试验结果中。下一步需在可合法复用已登录会话、且接口返回与已知3帖组完全一致的环境里验证分页后，才可大批量启动。

浏览器端实测在较长列表按`End`后约22秒可加载下一屏，先前普通滚动约64秒；这是单次页面操作的观察值，并非完整组吞吐量。页面初次载入仍约55秒，且长列表会虚拟化已滚出视野的帖子，因此每屏仍需立即保存ID并去重，不能仅在最后一次读取DOM。

## 并行页面测试

以上耗时均包含浏览器工具等待，不能解释为X服务器响应时间。最新测试同时加载3页：第一批约108秒得到3个明确无匹配页面；第二批约100秒读取3个非空页面首屏，继续一次PageDown后共保存12条关系（3个部分组）至`official_page_matches_batch.csv`。原始批次记录为`batch_20260929_01.json`及`batch_20260929_02.json`，日志为`batch_capture_log.jsonl`。采用每屏读取article主帖时间链接，避免把note引用和引用帖URL混入组成员。

这验证了少量并发可减少逐页串行的等待，尚未完成大规模稳定性测试。没有启动无人值守后台采集任务；当前已登录浏览器的后续分页需要继续执行。只要未确认列表末尾，均保留partial_page，不将首屏规模当作完整组规模。

2026-09-30续采后，汇总见`verified_groups_summary.csv`，逐帖成员及链接见`verified_groups_posts.csv`，嵌套分组信息见`verified_groups.json`。本轮汇总为11个非空note页面组、204条note—post关系，5个页面组读到当前列表末尾、6个仍为部分结果；另有3个明确空页。这些是note页面组，不能未经核查当作11个互不重叠的独立媒体内容组。已完成页的“完整”仅针对本次当前账号可见列表，不声称覆盖被删除、不可访问或未来新增的帖子。

尝试6页同批操作发生工具超时，恢复后采用每批最多3页。未完成页的浏览器标签和读取位置记录在`browser_resume.json`，续采无需重新打开已保留页面。每批确认的ID已在保存文件中去重，不以原帖ID补造页面成员。
